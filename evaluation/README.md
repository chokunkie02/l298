# ชุดข้อมูลประเมินผล OCR (Local Evaluation Dataset)

โฟลเดอร์นี้เป็นโครงสร้างสำหรับวัดความแม่นยำ OCR บนภาพจริงในเครื่องของคุณเอง
เปรียบเทียบโหมด preprocessing ต่าง ๆ (`none`, `resize`, `grayscale_clahe`,
`adaptive_threshold`) ก่อนตัดสินใจเปลี่ยนค่าเริ่มต้นของ production

**สิ่งที่ track ไว้ใน Git**: `README.md` นี้ และ `manifest.example.csv` (แม่แบบ
เท่านั้น ไม่ใช่ข้อมูลจริง)

**สิ่งที่ไม่ track ไว้ใน Git** (ถูกกันด้วย `.gitignore`): ภาพจริงในเครื่อง
(`evaluation/images/`), manifest จริงที่คุณสร้าง (`evaluation/manifest.csv`),
และผลลัพธ์การประเมิน (`evaluation/results/`) เพราะภาพและ ground truth เป็น
ข้อมูลส่วนตัวของผู้ใช้แต่ละคน ไม่ควรถูก commit เข้าไปในโปรเจกต์

## 1. รูปแบบไฟล์ manifest

ไฟล์ manifest เป็น CSV ที่มี 4 คอลัมน์ (ดูตัวอย่างใน `manifest.example.csv`):

| คอลัมน์         | ความหมาย                                                        |
|-----------------|--------------------------------------------------------------------|
| `image_path`    | ตำแหน่งไฟล์ภาพ สัมพัทธ์กับตำแหน่งไฟล์ manifest เอง (หรือ absolute path) |
| `ground_truth`  | ข้อความที่ถูกต้องจริงในภาพ (พิมพ์ด้วยมือ เป็นความจริงอ้างอิง)         |
| `language`      | `th`, `en`, หรือ `mixed` ใช้สำหรับจัดกลุ่มผลลัพธ์เท่านั้น              |
| `notes`         | หมายเหตุอิสระ เช่น "ภาพเอียง", "แสงน้อย" - ไม่ถูกใช้ในการคำนวณ         |

แถวที่ `image_path` ว่างเปล่าจะถูกข้ามไปเงียบ ๆ (ใช้เป็นแถวหมายเหตุได้)

**คำเตือน**: `manifest.example.csv` มีแถวตัวอย่าง 2 แถวที่ **ไม่มีไฟล์ภาพจริง
อยู่จริง** ใช้เพื่อสาธิตรูปแบบคอลัมน์เท่านั้น ห้ามรันเครื่องมือประเมินผลชี้ไปที่
ไฟล์นี้แล้วเข้าใจว่าได้ผลลัพธ์จริง ต้องสร้าง `evaluation/manifest.csv` ของคุณเอง
พร้อมภาพและ ground truth จริง

## 2. วิธีสร้างชุดข้อมูลของคุณเอง

1. สร้างโฟลเดอร์ `evaluation/images/` แล้ววางภาพจริงไว้ในนั้น
2. คัดลอก `manifest.example.csv` เป็น `evaluation/manifest.csv` แล้วแก้ไขให้
   ชี้ไปยังภาพจริงพร้อมพิมพ์ ground truth ด้วยมือให้ตรงกับสิ่งที่อยู่ในภาพ
   จริง ๆ (รวมช่องว่าง/เครื่องหมายวรรคตอนตามที่เห็นจริง)
3. แนะนำให้ครอบคลุมภาพลักษณะต่าง ๆ อย่างน้อยประเภทละ 1-2 ภาพ:
   - ข้อความไทยพิมพ์ ชัดเจน
   - ข้อความอังกฤษพิมพ์ ชัดเจน
   - ข้อความไทยปนอังกฤษ
   - ข้อความขนาดเล็ก
   - ภาพที่ถ่ายเอียง/หมุน
   - ภาพมืด
   - ภาพสว่าง/มีแสงสะท้อน
   - ภาพ contrast ต่ำ (ตัวอักษรกับพื้นหลังสีใกล้กัน)
   - ภาพเบลอเล็กน้อย (มือสั่นตอนถ่าย)
   - ภาพถ่ายจากกล้องโทรศัพท์จริงในสภาพแวดล้อมที่จะใช้งานจริง (ไม่ใช่ภาพ
     screenshot หรือภาพที่ generate ขึ้น)
4. แนะนำให้เริ่มต้นด้วยภาพอย่างน้อย 20-30 ภาพเพื่อให้ผลเป็นตัวแทนมากขึ้น
   แต่เครื่องมือประเมินผลทำงานได้แม้มีภาพน้อยกว่านั้น (แค่ผลจะแกว่งง่ายกว่า)

## 3. รันการประเมินผล

```bash
source .venv/bin/activate
python evaluate_ocr.py --manifest evaluation/manifest.csv
```

ตัวเลือกอื่น ๆ:

```bash
# ทดสอบเฉพาะบางโหมด
python evaluate_ocr.py --manifest evaluation/manifest.csv --modes none resize

# บันทึกผลละเอียดต่อภาพ/โหมดเป็นไฟล์ (นามสกุลกำหนดรูปแบบไฟล์)
python evaluate_ocr.py --manifest evaluation/manifest.csv --output evaluation/results/run1.csv
python evaluate_ocr.py --manifest evaluation/manifest.csv --output evaluation/results/run1.json
```

การรันครั้งแรกจะดาวน์โหลดโมเดล EasyOCR หากยังไม่เคยดาวน์โหลด (ดูหัวข้อ
"พฤติกรรมของโมเดล EasyOCR" ใน README.md หลักของโปรเจกต์) และการประมวลผลด้วย
CPU อาจใช้เวลาหลายวินาทีต่อภาพต่อโหมด

## 4. วิธีอ่านผลลัพธ์

- **CER (Character Error Rate)** คือตัวชี้วัดหลัก โดยเฉพาะสำหรับภาษาไทย
  คำนวณจากระยะแก้ไข (Levenshtein distance) ระดับตัวอักษรหารด้วยความยาว
  ground truth หลังทำ Unicode NFC normalization ยิ่งค่าน้อยยิ่งดี (0% = ตรง
  ทุกตัวอักษร)
- **whitespace-token error rate** เป็นตัวชี้วัดเสริมที่คำนวณจากการตัดคำด้วย
  ช่องว่างเท่านั้น **ไม่ใช่ความแม่นยำระดับคำภาษาไทยที่แท้จริง** เพราะภาษาไทยไม่
  เว้นวรรคระหว่างคำ ค่านี้มีความหมายเฉพาะข้อความอังกฤษหรือข้อความที่เว้นวรรค
  จริงเท่านั้น บันทึกไว้ในไฟล์ผลลัพธ์ละเอียด (`--output`) เพื่อการวิเคราะห์
  เพิ่มเติม แต่สรุปผลหน้าจอไม่ใช้ค่านี้ตัดสิน
- **mean_confidence ของ EasyOCR ไม่ใช่ตัวแทนความแม่นยำ** ห้ามใช้ค่า confidence
  เพียงอย่างเดียวเพื่อเลือกว่าโหมด preprocessing ใด "ดีกว่า" ต้องเทียบ CER กับ
  ground truth จริงเสมอ
- **exact_match_rate**: สัดส่วนภาพที่ข้อความที่อ่านได้ตรงกับ ground truth
  ทุกตัวอักษรพอดี (หลัง NFC normalization)
- ผลลัพธ์ถูกจัดกลุ่มแยกตามภาษา (`language` ใน manifest) และแยกตามโหมด
  preprocessing เพื่อเปรียบเทียบว่าโหมดใดช่วยภาษาใดได้จริงบ้าง

## 5. ความเป็นส่วนตัว

ภาพและ ground truth ในโฟลเดอร์นี้อยู่ในเครื่องของคุณเท่านั้น ไม่ถูกอัปโหลดหรือ
commit เข้า Git (ถูกกันด้วย `.gitignore`) และเครื่องมือประเมินผลไม่ส่งข้อมูล
ใด ๆ ไปยัง Serial หรือ ESP32
